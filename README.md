# 똥뚜 여행계획

아이폰 12의 390×844 화면을 기준으로 만든 모바일 여행계획 웹페이지입니다. 여행별 데이터와 공통 UI를 분리해 여행이 늘어나도 같은 화면과 기능을 재사용합니다. 실제 지도 타일과 도로 경로는 인터넷 연결이 필요합니다.

## 파일 구성

- `index.html`: 모든 여행이 공통으로 사용하는 화면 뼈대
- `assets/app.css`: 아이폰 12 기준 모바일 스타일과 공용 테마
- `assets/js/app.js`: 앱 초기화, 탭, 선택 상태와 화면 연결
- `assets/js/home.js`: 대한민국 발자국 지도와 국내·해외 기록 렌더링
- `assets/js/data-loader.js`: 매니페스트와 여행 JSON 로딩
- `assets/js/trip-model.js`: 여행 데이터 검증과 방문 장소 조회
- `assets/js/ui-state.js`: 마지막 선택 상태의 브라우저 저장
- `assets/js/schedule.js`: 일정 카드와 현재 일정 렌더링
- `assets/js/map.js`: Leaflet 지도, 마커, 경로와 이동거리 계산
- `data/trips.json`: 페이지에 표시할 여행 목록 매니페스트
- `data/trips/*.json`: 여행별 날짜·일정·장소·동선 데이터
- `data/footprints.json`: 일정 없이 보관하는 과거 여행·자주 가는 도시 기록
- `assets/maps/`: 홈의 대한민국 시 단위 발자국 지도와 출처
- `scripts/validate-data.mjs`: 여행 데이터와 id 참조 자동 검사
- `docs/data-format.md`: 새 여행 작성용 데이터 형식과 예제
- `package.json`: 별도 패키지 설치 없이 실행하는 검증 명령
- `robots.txt`: 검색엔진이 사이트를 수집하지 않도록 요청하는 설정
- `.nojekyll`: GitHub Pages가 파일을 그대로 배포하도록 하는 설정

## 일정 수정

`data/trips/`에서 해당 여행 JSON을 열고 날짜의 `rows`를 수정합니다. 일정 한 줄은 속성 이름이 드러나는 객체로 작성합니다.

```json
{
  "time": "14:00~14:10",
  "type": "move",
  "from": "여수엑스포역",
  "to": "이순신광장",
  "activity": "이동",
  "note": "택시"
}
```

새 여행은 `data/trips/`에 JSON 파일을 만들고 `data/trips.json`에 `id`와 파일 경로를 등록합니다. 여행 파일의 `version`은 현재 `2`이며 매니페스트의 `id`와 파일 내부 `id`가 같아야 합니다. `region`에는 네이버지도 검색에 사용할 지역명을 쓰고, `startDate`·`endDate`와 홈 지도에서 색칠할 `footprintCities`도 함께 작성합니다. `days`는 여행 날짜 순서대로 배열에 넣습니다. 장소나 이동 경로를 바꾸면 같은 날짜의 `visits`와 `segments`도 함께 수정합니다. `segments`의 이동 수단은 차량 `drive`, 도보 `foot`, 케이블카 `cable` 중 하나를 사용합니다.

일정 페이지가 필요 없는 과거 여행이나 자주 가는 곳은 `data/footprints.json`에만 기록합니다. 여행지는 기본적으로 시 단위 id로 연결하되 서울은 방문한 자치구 id로 연결합니다. 날짜가 있는 여행은 `startDate`와 `endDate`를 쓰고, 자주 가는 곳은 날짜를 생략합니다. 과거 발자국에는 일정 보기 버튼이 생기지 않고, 상세 여행 JSON이 있는 예정 여행만 홈에서 일정 탭으로 이동합니다.

홈 지도는 전체 보기에서 도 경계를 보여 주고, 두 손가락이나 ＋ 버튼으로 최대 12배까지 확대하면 전국 시 경계가 나타납니다. 서울만 한 단계 더 확대하면 구 경계가 나타나며 다른 지역은 시 경계를 유지합니다. 확대 상태에서는 한 손가락 또는 마우스로 지도를 이동할 수 있고, 짧게 누르면 지역을 선택하며 `전체` 버튼으로 처음 범위로 돌아갑니다.

시·군 경계는 지역별 SVG의 실제 외곽 범위를 전국 지도의 해당 도 외곽 범위에 맞춰 표시합니다. 남아 있는 미세한 도 면 노출 구간도 가장 가까운 시·군으로 연결되며, 서울 구와 일반 시·군 모두 선택 영역을 흰색 외곽선으로 표시합니다.

지도에서 발자국 지역을 누르면 지역명과 여행 기간을 확인할 수 있습니다. 여행 기간이 없는 자주 가는 지역은 중복 설명 없이 지역명만 표시하고, 회색 미방문 지역은 지역명과 미방문 상태를 표시합니다. 아래 국내·해외 발자국은 전체 기록을 유지하며, 서울의 상시 발자국은 방문한 구별로 표시합니다.

방문 장소와 이동 구간은 배열 번호가 아닌 고유 `id`로 연결합니다. 지도 장소를 일정 카드와 연결할 때는 해당 일정에 `visitIds`를 적습니다. 같은 장소를 다시 방문하면 좌표는 같아도 다른 방문 `id`를 사용합니다. 자세한 형식은 `docs/data-format.md`를 참고합니다.

수정 후 아래 명령으로 필수 속성, 중복 id, 잘못된 방문·구간 참조를 확인합니다.

```powershell
npm test
```

공통 화면이나 동작을 바꾸는 경우에만 `index.html` 또는 `assets/`를 수정합니다. 일정 추가를 위해 기존 여행 데이터나 공통 JavaScript를 복사하지 않습니다.

로컬에서 확인할 때는 JSON을 `fetch`할 수 있도록 저장소 루트에서 간단한 정적 서버를 실행합니다.

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

그다음 브라우저에서 `http://127.0.0.1:8765/`를 엽니다. PC에서 `index.html`을 직접 더블클릭하는 방식은 브라우저의 로컬 파일 보안 정책 때문에 여행 JSON을 불러오지 못할 수 있습니다.

지도는 OpenStreetMap을 사용하며 차량 경로는 OSRM, 도보 경로는 OpenStreetMap.de 경로 서버에서 실시간으로 불러옵니다. 경로 서버가 응답하지 않으면 해당 구간만 직선으로 표시됩니다.

지도 위의 `시작`과 `도착` 번호를 고르면 해당 번호 사이의 마커·동선과 아래 일정 카드만 표시됩니다. 부분 일정은 시작 장소의 활동부터 도착 장소의 활동까지 포함합니다. 여행 중 현재 위치에서 다음 장소로 가는 길만 보려면 같은 번호 구간을 선택하고, 다시 기차와 귀가를 포함한 하루 전체 일정으로 돌아가려면 `전체 동선 복원`을 누릅니다.

같은 장소를 하루에 다시 방문해도 번호는 장소 고유번호가 아니라 방문 순서대로 각각 부여합니다. 숙소처럼 출발과 복귀 좌표가 같으면 전체 지도에서는 `1·9`처럼 하나의 마커에 번호를 함께 표시하고, 구간 선택창과 일정에서는 모두 `숙소`로 표시해 방문번호로 구분합니다.

지도는 선택 구간의 시작·도착 장소명만 항상 표시하고, 중간 장소는 번호 마커를 누르면 이름이 나타납니다. 번호를 누르면 지도 안의 미니카드에서 방문시간과 일정, 네이버지도 링크를 함께 확인할 수 있습니다. 마지막으로 선택한 여행·날짜·일정/지도 화면·시작/도착 구간은 현재 브라우저에 저장되므로 같은 기기에서 다시 열거나 새로고침해도 그대로 이어집니다.

여행 당일 해당 날짜를 선택하면 날짜 정보 아래에 현재 일정과 바로 다음 일정이 표시됩니다. 이 요약을 누르면 현재 시간에 해당하는 일정 카드로 이동하며, 시간 경과에 맞춰 자동으로 갱신됩니다.

## 여행계획 작성 스타일

### 기본 방향

- 유명 관광지를 많이 넣는 것보다 실제 이동 동선과 여행 만족도를 우선합니다.
- 일정은 여유 있게 구성하되 불필요한 대기시간이나 같은 지역 재방문은 줄입니다.
- 음식점 하나를 위해 `A → C → B`처럼 우회하지 않습니다. 식당은 관광 동선 위나 다음 목적지 방향에서 선택합니다.
- 같은 권역의 장소는 가능한 한 하루에 묶고, 이미 방문한 권역을 다른 날 다시 넣지 않습니다.
- 쇼핑 일정은 별도 요청이 있을 때만 추가합니다.

### 일정 작성 순서

1. 기차·항공편, 체크인·체크아웃, 경기·공연처럼 시간이 고정된 일정을 먼저 배치합니다.
2. 숙소 위치와 귀가 동선을 기준으로 하루의 시작점과 종료점을 정합니다.
3. 관광지와 식당을 권역별로 묶어 이동이 자연스럽게 이어지도록 배치합니다.
4. 대중교통·택시·도보 이동시간과 필요한 대기시간을 일정표에 포함합니다.
5. 날씨 영향을 크게 받는 여행지는 맑은 날 일정과 비 오는 날 대체 일정을 분리합니다.

### 시간 기준

- 일정표에는 `10:50~11:00`처럼 애매한 도착 범위를 쓰지 않고 명확한 시작·종료 시각을 사용합니다.
- 지도 앱의 예상 이동시간보다 필요한 경우 5~10분 정도 여유를 반영합니다.
- 앞 일정이 끝나면 특별한 휴식 계획이 없는 한 바로 이동하는 것으로 작성합니다.
- 준비시간은 여행자가 지정한 시간을 우선하며, 남는 시간을 만들기 위해 임의로 늘리지 않습니다.
- 일반적인 식사시간은 1시간을 기본으로 합니다.
- 카페와 주변 구경은 합쳐서 약 1시간 30분을 기본으로 하되, 서로 다른 장소라면 행을 분리합니다.
- 박물관·전시·관광지의 체류시간은 규모와 실제 관람량을 확인해서 정합니다.

### 일정표 표현

- 열 순서는 `시간 / 출발지 / 도착지 / 일정 / 비고`로 고정합니다.
- 이동 행에는 실제 출발지, 도착지, 이동수단과 현실적인 소요시간을 표시합니다.
- 장소가 바뀌면 구경과 카페처럼 연속된 활동도 각각의 목적지가 드러나도록 분리합니다.
- `비고`에는 음식 종류, 대표 메뉴, 이동수단, 예약·대기 또는 날씨 관련 주의사항처럼 실제로 필요한 정보만 씁니다.
- 여행 탭 이름은 `YY.MM.DD~YY.MM.DD/지역` 형식을 사용합니다.
- 지도에는 실제 지도와 실제 도로 경로를 사용하고, 방문 순서 번호와 이동수단별 선 모양을 구분합니다.

### 판단 기준

- 후보지가 여러 개면 숙소와 고정 일정까지의 이동시간, 해당 지역만의 여행 느낌, 날씨 영향을 함께 비교합니다.
- 이동시간이 긴 후보지는 당일 고정 일정에 무리가 없는지 먼저 확인합니다.
- 이미 다른 날 방문하는 지역과 분위기나 볼거리가 크게 겹치는 후보는 우선순위를 낮춥니다.
- 사용자가 확정한 장소·식당·시간은 임의로 다른 후보로 바꾸지 않습니다.

## 이력 관리

이 폴더는 `C:\my\TravelPlans` 독립 Git 저장소입니다. 저장소 루트에서 수정 내용을 확인하고 기록합니다.

```powershell
git status
git add AGENTS.md README.md index.html assets data robots.txt .nojekyll
git commit -m "feat(travel): 새 여행 일정 추가"

```

GitHub Pages는 `main` 브랜치의 저장소 루트에서 배포합니다.
